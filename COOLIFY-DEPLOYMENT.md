# Fund Planner on Coolify

Since this is a test setup for hs-accounts on the existing Coolify instance.

## How it is deployed

```
git push origin main
      |  (GitHub App webhook, Auto Deploy = on)
      v
Coolify app "hs-accounts"  (project: sok-remaster, build pack: dockercompose)
      |  build pack: dockercompose, file: docker-compose.coolify.yml
      v
  backend  container   host network, uvicorn on 127.0.0.1:8000
  frontend container   nginx serving the ERPNext site, published on 127.0.0.1:8180
      ^
  host nginx (80/443, TLS from Let's Encrypt)
      /api/, websocket   -> 127.0.0.1:8000
      everything else    -> 127.0.0.1:8180
```

- **One compose file, one Coolify app, two services.** A push rebuilds and restarts both.
- **MariaDB and Redis are not in Coolify.** The backend runs with `network_mode: host` and
  uses the host's own MariaDB (database `hs_accounts`) and Redis.
- **Uploads** live on the host at `/opt/hs-accounts/site/`, bind-mounted into the
  backend container and served by host nginx.
- **TLS and the public entry point stay on host nginx**, config at
  `/etc/nginx/sites-available/hs-accounts`. Coolify's own proxy is not used for this app.
- Both container ports are loopback-only; nothing is reachable except through host nginx.

### Environment variables (set in Coolify, app > Environment Variables)

`DB_NAME`, `DB_ROOT_PASSWORD`, `ADMIN_PASSWORD`, `FRAPPE_API_KEY`, `FRAPPE_API_SECRET`,
`TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_CHAT_IDS`.

`DB_ROOT_PASSWORD` is load-bearing: a different value makes the site inaccessible. Keep a copy.

### Before you push

A bad commit replaces the running container and takes the API down until the next good deploy.
Minimum check:

```sh
python3 -I - <<'EOF'
import ast, pathlib
for p in pathlib.Path('apps').rglob('*.py'):
    ast.parse(p.read_text(), str(p))
print("ok")
EOF
docker compose -f docker-compose.coolify.yml config -q
```

**Note:** For the watcher/bot services, `env_file: .env` was removed because `.env` is
gitignored. Environment variables are now set directly via `environment:` in the compose
file with defaults (e.g. `TELEGRAM_BOT_TOKEN: ${TELEGRAM_BOT_TOKEN:-}`). Set their values
in the Coolify UI under the app's Environment Variables.

## Database, migrations and schema changes

**Nothing runs automatically on deploy, and nothing changed with the move to Coolify.**

- MariaDB is schemaless and lives outside the containers, so a deploy never alters data.
- On startup the backend only seeds the administrator user and starts the
  background scheduler. There is no migration framework and no startup migration step.
- The app code sits in a volume (`site-code`), which a rebuilt image does not overwrite,
  so in-app upgrades are done through the Frappe UI (System Manager > Help > Check for updates).
- **Take a backup before running any migration**: `mysqldump --all-databases > /path/to/backup.sql`

## Backups

### a. Application data (the important one)

- **On demand:** Use `mysqldump --all-databases > backup.sql` and copy the site folder:
  `cp -r /opt/hs-accounts/site/ /path/to/backup/
- **Caveat:** the site folder is managed by the frappe user; ensure permissions are correct.

### b. The Coolify instance itself

Same as documented in the fundplanner setup.

## 3. Running

Needs Docker with Compose v2.

1. Open the Coolify UI and ensure the app "hs-accounts" is running.
2. Open the site in a browser, log in as `Administrator` / `admin` (set in `.env.example`),
   and finish the ERPNext setup wizard. A Company is needed before Cost Centers exist.
3. The API key and secret are generated by running `scripts/dev.sh keys` locally,
   then update the Coolify app's environment variables.
4. The folder watcher runs in the container by default (logs at /proc/1/fd/0).
5. Optional Telegram: create a bot with @BotFather, put the token and your chat ids in `.env`.

## 4. Migration to Coolify

If this is the first time deploying, clone the repo and create a `.env` file:

```sh
cd /home/sok/Developer
git clone https://github.com/omshivaprakash/hs-accounts.git hs-accounts
cd hs-accounts
echo "DB_NAME=hs_accounts" > .env
echo "DB_ROOT_PASSWORD=<some-password>" >> .env
echo "ADMIN_PASSWORD=<some-password>" >> .env
```

Then:

1. Add the app to Coolify (app name: "hs-accounts")
2. Set the build pack to "Docker Compose" and file to "docker-compose.coolify.yml"
3. Add environment variables in the Coolify UI (or via API)
4. Set up host MariaDB and Redis with the database `hs_accounts`
5. Set up host nginx config serving from `/opt/hs-accounts/site/` (see fundplanner deployment)
6. Redeploy the app

## 5. Troubleshooting

| Symptom | Likely cause / fix |
|-----|----|
| Deploy fails with `additional properties '...' not allowed` | Compose YAML broken (indentation). `docker compose -f docker-compose.coolify.yml config -q` locally. |
| Deploy "finished" but API is 502 / health fails | Container crash-looping: `docker logs hs-accounts-backend-1`. Usually a Python syntax/import error. Fix and push, or stop the app and restart it manually. |
| Port 8000 already in use | Another service is running on that port. `lsof -i :8000` to find it. |
| MariaDB connection fails | Host MariaDB not running, wrong database name or credentials. |
| Users logged out after a deploy | `ADMIN_PASSWORD` changed in Coolify. Restore the old value and redeploy. |
| Frontend calls the wrong API host | `FRAPPE_API_KEY`/`FRAPPE_API_SECRET` are baked into the JS bundle at build time; fix them and redeploy. |
| Uploaded files 404 | `/opt/hs-accounts/site/` missing or wrong permissions; nginx serves it directly. |
